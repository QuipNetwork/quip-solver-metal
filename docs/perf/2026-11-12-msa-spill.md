# Multi-spin spill measurements, 2026-11-12

The weighted multi-spin annealing (MSA) kernel now runs models with more nodes than threadgroup memory holds. Words `0..K` stay in threadgroup memory and words `K..N` stay in device memory, where `K` is 6,016 on every Apple GPU. At degree 20, this layout is 2 to 8 percent faster than a layout with every word in device memory. At degree 40, the difference is within run-to-run noise, so the kernel keeps the threadgroup prefix. Models that fit threadgroup memory run the same pipelines as before, and their Advantage2 rate does not change.

## Host and load

The host was an Apple M4 Max with 128 GiB of memory, measured on 2026-11-11 between 21:07 and 21:33 local time. Other agents used the host during every run. The one-minute load average was between 3.9 and 15.7. Each script records `uptime` before and after its runs. Because of this load, the comparisons below use runs of the two builds that alternate in one script, not runs at different times.

## Commands and method

The baseline is commit `1e95796` in a separate worktree. Both worktrees share one Cargo target directory, so each build first touches its sources, and the script copies the test binary to a scratch directory before the next build. A check on the kernel text inside each binary (`grep -c QUIP_MSA_SPILL`) confirms which build each copy holds.

```sh
QUIP_PM1_SCALE=wide QUIP_PM1_KERNEL=Msa ./pm1-base pm1_rates --ignored --nocapture
QUIP_PM1_SCALE=wide QUIP_PM1_KERNEL=Msa ./pm1-spill pm1_rates --ignored --nocapture
cargo test --release --test msa_spill -- --ignored --nocapture --test-threads=1
```

`pm1_rates` runs eight ±1.5 jobs on the 4,577-node Advantage2 topology with 64 reads and 4,096 sweeps per job. `median_s` is the upper middle of the eight sorted job times. `spill_layout_rates` in `tests/msa_spill.rs` runs milli circulant models with 128 reads and 256 sweeps at 4 sweeps per rung. It reports the median GPU time of three runs and the word updates per second, where one word update advances 32 replicas of one spin. The `device` layout is the same spill build with `K = 0`, so every word is in device memory, which is the layout that `kernels/msa64.metal` tested. Each model runs the prefix layout before and after the device layout, and the three runs return equal reads.

## Advantage2 rate

The first build chose between the two layouts at run time, inside one pipeline. In eight alternating pairs over two scripts, that build was 0.9 to 2.6 ms slower than the baseline in every pair, about 0.4 percent. A copy of that build without the device-memory branch matched the baseline. For this reason, the spill layout is a compile-time define, `QUIP_MSA_SPILL`, in two new pipelines: `msa_weighted_spill` (milli `int` coefficients and the dense-row code) and `msa_float_spill`. The host selects them only for a model of more than `K` nodes.

At degree 20 the prefix layout is 7.8 percent faster on 20,000 nodes and 2.0 percent faster on 60,000 nodes. The gain falls as `K / N` falls. At degree 40 the device layout is 0.9 percent faster, which is less than the spread of the prefix layout on the same model on the same day (477 to 508 ms). The prefix layout stays because no model ran slower on it by more than noise.

## Largest model

`a_200k_node_model_completes` runs 200,000 nodes and 4,000,000 edges at degree 40 with 128 reads and 16 sweeps. It ran in 4 command buffers. The largest took 94.0 ms of GPU time, and all four took 323.2 ms. The 500 ms dispatch ceiling holds with the existing cost factors, so this change adds no spill cost factor.

## Threadgroup memory

Every MSA pipeline declares 128 static bytes, the 32 lane totals. The host adds the spin words: `N * 4` bytes rounded up to 16 for a model that fits, which is 18,320 bytes for Advantage2, and `K * 4 = 24,064` bytes for a spilled model. A spilled dispatch uses 24,192 bytes of the 32,768 available.
