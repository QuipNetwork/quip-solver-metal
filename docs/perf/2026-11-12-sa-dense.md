# Dense matrix simulated annealing measurements, 2026-11-12

The dense-matrix SA kernel, `kernels/sa_dense.metal`, reads one row of an `N * N` coupling matrix each time a spin flips. It returns the same reads as the sparse SA kernel for the same seed. The cost of a sweep depends on how many spins flip, because a flip walks `N` matrix columns and a rejected update does not. The sweeps at the hot start of the schedule are the slowest, so the rate in the code comes from them.

The slowest single chunk ran at 5.76 million columns per second: one sweep of the Int8 model of 4,898 nodes, 4,165 ms. The planner and the admission limit both use one constant, `SA_MATRIX_COLUMNS_PER_SEC = 5.0e6`, which is 13 percent under that rate. A chunk holds at least one sweep, so the admission refuses a dense-matrix SA model whose one sweep the planner estimates at more than 400 ms. That limit is 1,414 nodes at every precision and read count. At the limit, the longest measured chunk was 328.5 ms (Int8 and Binary models, one sweep). Where a chunk holds more than one sweep, the longest measured chunk was 170.1 ms, at 1,024 nodes.

The limit is low because memory latency limits the kernel. One flip of a 1,414-node model reads and writes 1,414 deltas per read, and each SIMD group of 32 reads does this at about 6 to 10 million columns per second.

## Host and load

The host was an Apple M4 Max with 40 GPU cores. The runs took place on 2026-11-12 between 02:55 and 03:15 local time. Other agents used the host during the runs. The one-minute load average was between 5.4 and 6.0 shortly after the runs.

## Commands and method

```sh
cargo test --release --test sa_dense dense_rates -- --ignored --nocapture
cargo test --release --test sa_dense the_largest_admitted_dense_sweep_runs -- --ignored --nocapture
```

`dense_rates` in `tests/sa_dense.rs` runs complete models with a planted ground state at each precision. Every run has 256 reads, the batch path's read cap (`MAX_READS`). The test checks that all 256 reads come back. It uses the production chunk plan and the default beta schedule, and it records the total GPU time, the chunk count, and the longest chunk's GPU time.

One column walk is one flip times one matrix column. The rate column assumes that every spin flips in every sweep, so a sweep of an `N`-node model counts as `N * N` columns. The number is a lower bound on the true rate when few spins flip, and close to exact at the hot start. The rate divides the columns by the total GPU time, so it averages hot and cold sweeps. The slowest chunk runs at a lower rate.

The kernel is the same at every read count up to 256. The SIMD groups of a dispatch run side by side, so the time of one sweep does not depend on the read count. Splitting the 256 reads into eight threadgroups of one SIMD group each, instead of one threadgroup, did not change the rates.

## One-sweep limit

The admission estimates one sweep as `N * N` columns at 5.0e6 columns per second, without the planning margin. Every SIMD group walks its rows at once, so the estimate does not depend on the read count. The estimate passes 400 ms past 1,414 nodes (1,414 nodes give 399.88 ms and 1,415 nodes give 400.445 ms). The admission refuses a model past the limit with `SampleError::TooLarge`, which the harness reports as `Capacity`, before any buffer exists. The unit test `a_dense_sa_sweep_past_one_chunk_is_refused_before_allocation` in `src/sampler.rs` checks both sides of the limit.

At the limit, one sweep of an Int32 model of 1,414 nodes with 256 reads measured 182.4 ms in `the_largest_admitted_dense_sweep_runs`. The Int8 and Binary models measured 327.0 and 328.5 ms in `dense_rates`. The margin of the slowest shape under 400 ms is 18 percent. It covers the quiet rate with room for light contention, and it does not cover every load.

## Effect on routing

The capacity model routes a model to dense storage when the dense matrix takes fewer bytes than the CSR arrays. For SA this happens for models with more than about a fifth of the possible couplers, or half for Int32 and Float32. A model of more than 1,414 nodes in that range now fails the one-sweep check. Before this change it ran on the sparse global build, whose chunk plan assumes a sparse model. This document did not measure the sparse build on such a model.
